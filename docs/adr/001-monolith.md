# ADR-001: Модульный монолит для быстрого старта

- Status: Accepted
- Date: 2026-04-05

## Context
Требуется определиться с архитектурой приложения на основе ряда требований:
Фаза: MVP → ранний рост (частые изменения требований)  
Цель: быстро выпускать фичи  
Нагрузка: умеренная (не hyperscale), но пики возможны (распродажи)

## Decision
Разработать модульный монолит с четко определенными границами между модулями

## Alternatives considered
1. Обычный монолит без границ
2. Микросервисы

## Consequences
Pros:
- Меньше конфигов и компонентов со стороны инфраструктуры
- Меньше времени требуется на сборку/деплой сервисов
- Быстрая разработка за счет отсутствия реализаций дополнительного кода в виде интеграций между сервисами
- Простой переход на микросервисы, т.к. заранее заложены границы

Cons / Risks:
- С ростом нагрузки может понадобиться переход на микросервисы
- Используются общие технологии/библиотеки
- В большой команде могут часто возникать конфликты из-за затрагивания одного и того же участка в коде
- UI и все модули деплоятся вместе одним заходом
- Нельзя отдельно масштабировать горячие модули
